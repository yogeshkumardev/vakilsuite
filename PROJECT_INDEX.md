## Architecture and repositories

Web and Android use FastAPI `/api/v1`. PostgreSQL owns domain records and durable job state;
Redis supports throttling and Celery transport; private R2 stores document bytes.
Uploads use presign → direct R2 transfer → API confirmation. Explicit source/OCR,
summary, working-document and legal-research workflows now exist in source.

This is a single Git monorepo: backend, frontend, Android, contracts, scripts and the
shared Word editor are tracked from the repository root. Run status/diff from the root.
The root ignore policy excludes local secrets, generated dependencies, build output and
device artifacts; do not force-add them.

Test deployment is defined by [`render.yaml`](render.yaml): one API, one Celery worker,
one Celery beat service, Postgres and Key Value. The Vercel project root is `frontend/`;
its config builds the linked browser DOCX editor. Follow
[`docs/deploy-vercel-render.md`](docs/deploy-vercel-render.md) for secrets, CORS, R2 and
acceptance checks. Do not treat a Vercel preview URL as an approved API origin.

## Constraints and setup gaps

- Preserve server-side resource permissions, chamber/account isolation and stale-request guards.
- Upload/save alone must not silently start paid AI work. Inspect explicit submission and provider policy.
- Preserve source provenance, review decisions, revision concurrency and idempotent retries.
- Current web workspaces use the DOCX editor. Legacy editor-shaped JSON remains only as a
  persistence compatibility format; inspect the caller before changing that conversion.
- Frontend links the shared editor to `../packages/docx-editor/packages/`. `./scripts/dev.sh`
  installs and builds that package when required before starting the complete stack. For a
  database managed separately, use `./scripts/dev-backend.sh` (API + Celery worker) and
  `./scripts/dev-frontend.sh` (Next.js) in separate terminals.
- Legacy routes remain gated; inspect the web feature gate and actual consumers before reuse.
- Preserve migration history. Never reset data or accept autogenerated drops blindly.
- Court-format YAML is deterministic, source-cited configuration. Resolve it through
  `backend/app/features/court_rules/`; do not place court rules in prompts or a RAG corpus.
- Earlier setup/sprint/POC documents referenced by the old index are absent in this checkout.
  Use current code and user-authorized scope; sprint names in comments do not establish approval.

## Checks and maintenance

Run `node scripts/check-project-index.mjs` after changing navigation docs.
For API changes, regenerate with `node scripts/sync-api-contract.mjs`, review all copies,
then run `node scripts/sync-api-contract.mjs --check`. App checks live in each map.

Update the affected map when routes, entry points, workflow boundaries or test ownership change.
Keep versions in manifests, exact payloads in schemas, and transient Git/test status out of indexes.
Do not load generated schemas/types, lockfiles or every app map for unrelated work.
